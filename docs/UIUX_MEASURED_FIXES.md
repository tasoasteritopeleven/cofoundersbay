## Findings and changes

- `/admin/dashboard`: axe `definition-list` (serious, one `dl`) and `dlitem` (serious, two nodes). The memory `dt`/`dd` lived inside an extra `div` and the progressbar was inside the `dl` after that row. Split the three health entries into valid description lists and keep the progressbar immediately after the memory pair, outside its `dl`, preserving the order, spacing, and existing EN/EL strings.
- Shared `RailStats`: the same nested-`div` description-list pattern existed in rail stat rows (not a separate violation recorded on a completed route in this file). Removed the nested wrapper, retaining term/value association, value-above-label layout and icon decoration via positioned term content. Added a focused adjacent test asserting the term and value are direct children of one group. Recheck a populated rail in both languages.
- `/admin/taxonomy`: axe `select-name` (critical, one native category filter `select`). Gave the filter a bilingual programmatic name. Its adjacent search input was verified from source to have only a placeholder, so it also gets a bilingual programmatic name.
- The audit's `unnamedVisibleControls` list is a **separate heuristic**, not an axe violation. Inspected the source for each control changed: `/admin/communities`, `/admin/feature-flags`, `/discover` (shared `SearchFilters`), `/feed` post composer, `/groups/manage`, `/groups/moderation`, `/help`, `/investor/scouting`, and `/investor/watchlist` have placeholder-only search/composer fields, without a label or ARIA name. Added bilingual `aria-label` to those specific fields; did not blindly change every heuristic hit (including `/ai`, which needs separate component inspection). Placeholder copy and input behavior remain unchanged.
- Local axe `color-contrast` (serious): `/discover` default profile fallback/match chip (dark tinted primary foreground 3.71/3.99:1), headline/location (dark muted text 4.08:1); `/events` small avatar initial, `/groups` small count chip, and `/investor/scouting` featured badge (primary text on 20%-tinted primary, measured 4.43:1); `/help` selected-topic count (white on a translucent light-primary surface, 3.68:1). Adjusted only the corresponding local text/background classes: lighter foregrounds on dark discovery cards, lighter primary tint on the three light surfaces, and an opaque light surface with accessible primary text on the help count. These are candidates pending a rendered axe recheck; do not treat class inspection as a measured pass. `/invite` also has a recorded 4.43:1 contrast node with only the selector `.bg-primary/20`; the sanitized report does not identify the source text element, so it is intentionally **not** changed without a verified match.
- No `aria-required-children`, `aria-required-parent`, or tablist-related axe violation appears in the completed rows of this JSON. The admin tab strip's extra group headers are already `aria-hidden` and its Radix tabs are direct children. No speculative tablist rewrite was made; check it again on an admin-role render (this run used existing-founder role).

The completed `docs/audit/REPORT.md` and `results-{390,1440}.json` added these findings after the first edit:

Compare preview identity by `id` rather than JSON and leave the already-restored user alone.
