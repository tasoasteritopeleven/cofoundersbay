# Parea → CoFounderBay: συγκριτικός έλεγχος και σχέδιο μεταφοράς

**Σύσταση:** πρώτα βελτιώνουμε το ήδη υπάρχον «Συνεχίστε»: μία πραγματική εκκρεμότητα, σαφής προορισμός και ίδια απάντηση από το AI. Δεν αντιγράφουμε εφαρμογή εξόδων, ούτε προσθέτουμε δεύτερο κέντρο εντολών. Ακολουθούν η σύνοψη επιστροφής, η ανάκαμψη και οι επόμενες ενέργειες στις βασικές ροές.

## 1. Βάση και όρια

Πηγές: καθαρά Git checkouts στο Linux, Parea `197d8cf` και CoFounderBay `aa449e29`. Δεν είχαμε πρόσβαση σε αδημοσίευτη εργασία στα Windows. Το σχέδιο διακρίνει **πηγαίο κώδικα**, **νέο browser observation**, **αρχειακό τεκμήριο** και **πρόταση**. ## 2. Σύγκριση με κρίση μεταφοράς

| Πεδίο | Υπεροχή Parea | Υπεροχή CoFounderBay / απόφαση |
|---|---|---|
| AI | Ρητό offline/local fallback, ήρεμα previews, what’s new. | Typed tool catalog, roles, endpoints και ελεγμένη αναίρεση. Ενισχύουμε υπάρχον fallback, όχι δεύτερο registry ή υπόθεση περί δεδομένων. |
| Onboarding | Άμεσα αναγνωρίσιμο αποτέλεσμα των επιλογών στην Αρχική. | Conversational onboarding, draft ανά χρήστη, safe return-to και role homes ήδη υπάρχουν. Δανειζόμαστε την ορατή συνέχεια, όχι νέο wizard. |
| Πλοήγηση / IA | Ρυθμιζόμενες γρήγορες διαδρομές, αφαίρεση άσχετων προορισμών από Continue. | Roles, page registry, command palette, έξι pins και PageRail. Ένα store· καμία απαιτούμενη χειρονομία. |
| Components | Shared controller, μία εργασία ανά surface, responsive αποκάλυψη. | Καλύτερος διαχωρισμός App Router/κοινό shell/domain components. Εξάγουμε αποδεδειγμένα κοινή λογική, όχι theme wrappers. |
| Loading/empty | Σαφές recovery και συγκεκριμένο «τι ακολουθεί». | `RouteError`, `EmptyState`, `NoFilterResults`, `FailedLine` και εικονογράφηση υπάρχουν· δεν εισάγουμε τέταρτο empty primitive. |
| Ειδοποιήσεις / loyalty | Return line, φυσική επανεπαφή μετά την πράξη, εμφανή επόμενα βήματα. | Ήδη triage, prefs, digest, quiet hours, saved και home/calendar sync. Βελτιώνουμε την αξία, όχι τον όγκο email/push. |
| Gamification | Πρόοδος από έγκυρη πράξη, τοπικός χρόνος, ιδιωτική αμοιβαιότητα. | Υπάρχουν επιτεύγματα, φήμη και ορόσημα. Όχι σήματα για views, μηνύματα χαμηλής αξίας ή χρήση του AI. |
| i18n | Επιμελημένα ελληνικά, sentence case, σύντομη μονόγλωσση προβολή. | `BilingualText` και περισσότερες locales. Όχι αντιγραφή του `t(el,en)`, ούτε ποσοστό ελληνικών ως απόδειξη ποιότητας. |
| A11y | Effective hit areas, Escape και stacking μεταξύ overlays. | Main landmarks, phone floors και axe/contract tests. Προσθήκη σύνθετων keyboard σεναρίων, όχι διακοσμητικού gesture. |
| Performance | Χωριστό φόρτωμα βαρύτερης λειτουργίας, bounded idle και data-saver guards. | RSC/cache/prefetch ήδη ενεργά. Μετράμε πριν προσθέσουμε prefetch ή αλλάξουμε chunks. |
| Testing | E2E ολόκληρης ροής, contrast και emulator χωριστά. | AST/contract, axe+census, compiled isolated API. Κοινή αποδοχή routine + failure + AI/manual parity. |

## 4. Χωροθέτηση και δεδομένα

**#12 — First pilot:** The event's organizer (the model has no co-host role) can confirm attendance on the event page from the start until seven days after it ends. RSVP intent alone never grants access. Confirmed attendees can privately select other confirmed attendees after the event ends; a mutual selection sends two in-app notices and offers the existing connection flow, without creating a connection. An event without an end uses the existing one-hour estimate. New selections close after 14 days. Unmatched rows are purged on read and by a periodic worker. Mutual matches can be withdrawn by either member at any time; withdrawal or correction of attendance removes both choices without a new notice. Account deletion cascades through the attendee rows. The assistant uses the same authenticated endpoints and page controls.

1. **Συγκεκριμένο σημείο ελέγχου: ειδοποιήσεις.** `components/common/NotificationCenter.tsx` (prop-driven, `read`) και `components/notifications/NotificationCenter.tsx` (queries/ socket, `readAt`) μοιράζονται όνομα/προϊόν αλλά όχι contract. Με απευθείας αναζήτηση βρέθηκε το re-export `components/common/index.ts`, όχι ενεργός JSX καταναλωτής αυτών των δύο. Δεν αποδεικνύει ότι είναι ασφαλές να διαγραφούν (έλεγξε barrels/dynamic imports/externals). Οι τρέχουσες εμφανείς surfaces είναι `app/notifications/page.tsx`, `NotificationsBell` και `LiveNotices`. Το policy μπορεί να ανήκει στο domain `lib/notification-chat.ts`, όχι σε νέο κοινό notification center.
2. **Domain component με δύο επίπεδα.** `app/messages/components/EnhancedMessageThread.tsx` και `components/messages/MessageThread.tsx` / `components/chat/UnifiedChatPopup.tsx`: review ownership του selection και focus, όχι συγχώνευση HTML εκ προοιμίου. Route-only dialog (`app/messages/ComposeMessageDialog.tsx`) μπορεί να μείνει route-owned. Μόνο ό,τι αποδεδειγμένα χρειάζονται πολλοί καταναλωτές πάει σε shared domain component.
3. **Resume presentation έναντι πολιτικής.** `HomeContinue` ήδη βρίσκεται στο founder dashboard και επαναχρησιμοποιεί `HomeNextStep`. Ο επιλογέας δεν πρέπει να μείνει στην AI UI ούτε να δημιουργεί δεύτερη πηγή αλήθειας. `HomeToday` αντλεί ήδη typed actionable rows· κρατάμε αυτήν τη σχέση αντί να σκορπίσουμε reminder widgets.
4. **Επεξεργασία ≠ πλοήγηση ≠ AI πρόταση.** Profile, search filters, onboarding draft και settings έχουν διακριτές πηγές. Δεν χρησιμοποιούνται chat messages ως database ούτε React state ως permission gate. Stable IDs για navigation, row options και invalidation. Έλεγξε πως ένα επιτυχημένο write ενημερώνει όλες τις πραγματικές views με ίδιο `qk`, και ένα failed write δεν εκπέμπει επιτυχία. Μη μοιράζεσαι AI threads με ανθρώπινα DMs, private choices με δημόσια σήματα, demo με παραγωγή ή readiness rubric με προσωπικούς βαθμούς.
5. **Μία θέση ανά ενέργεια.** Modal/top bar = context, κύρια ενέργεια = στην εργασία/κάρτα, action menu = δευτερεύουσα, rail = συναφείς ομάδες, AI = ίδια action IDs. Οι απλές lists δεν αποκτούν rail για να χωρέσουν δεύτερο κουμπί. Κανένα global state/theme per page και καμία μεταφορά Firestore, Zustand, routes, mascots ή asset bundles από Parea.
